First release of **dhcp-snooping-82**, a transparent DHCPv4 Option 82 agent and DHCP snooping for Ubiquiti airMAX stations in bridge mode. It is a drop-in replacement for the airOS `/bin/dhcp-fwd`.

Tested on a PowerBeam 5AC with airOS WA.v8.7.11 (Station WDS, kernel 2.6.32). The binary in this release is the one running on that station in production.

## Highlights

- Option 82 is added exactly once to every DHCP client packet from a customer port, **including unicast renews and rebinds**. `giaddr` and `hops` are never touched; the upstream relay sets them.
- Existing Option 82 is never overwritten. Our own Option 82 is stripped from replies, and each reply goes only to the port it belongs to.
- Built-in DHCP snooping: rogue DHCP servers on customer ports and requests from other subscribers arriving from the uplink are dropped.
- **No duplicates by design** (ebtables broute plus `AF_PACKET` sockets bound to the bridge ports) and **fail-closed** behaviour.
- Auto-configuration: every bridge with the DHCP relay enabled in the airOS UI; `ath*` ports are trusted, `eth*` ports are untrusted, with or without VLANs.
- Explicit ports for UI integration: `dhcp-fwd -n -u br1:eth0 -t br1:ath0.1284`.
- Circuit ID `<hostname>/<bridge>:<port>`, remote ID = bridge MAC (both templates).
- Static MIPS32r2 big-endian binary (about 140 KB), unprivileged packet worker, logs in RAM only, reproducible build, MIT license.

## Install

```sh
# on the PC
sha256sum -c SHA256SUMS
tar xzf dhcp-snooping-82-0.1.0-mips.tar.gz
cd dhcp-snooping-82-0.1.0
scp -O dhcp-fwd dhcp-snooping-82.sh dhcp-snooping-82.conf root@DEVICE:/tmp/

# on the device
sh /tmp/dhcp-snooping-82.sh install
/etc/persistent/dhcp-snooping-82/dhcp-snooping-82.sh activate
# enable "DHCP Relay" (Option 82) for the bridge in the web UI and press Apply
/etc/persistent/dhcp-snooping-82/dhcp-snooping-82.sh status
# when everything works, save to flash:
sh /etc/persistent/dhcp-snooping-82/dhcp-snooping-82.sh install --save
```

`install` and `activate` work while the relay is still disabled. Enabling it afterwards means the original `dhcp-fwd` never runs in between.

Back to the original: `dhcp-snooping-82.sh deactivate`. Remove completely: `dhcp-snooping-82.sh uninstall --save`.

## Known limitations

- Standard airOS firmware runs no boot scripts. After a reboot the original `dhcp-fwd` runs until `dhcp-snooping-82.sh ensure` is called, e.g. by a management system over SSH. On CS (custom script) firmware, the boot hook in `/etc/persistent/rc.poststart` does this automatically.
- airOS flushes ebtables on every "Apply"; the agent re-installs its rules within 5 seconds.
- `--check` and `--status` must be given the same `-u`/`-t` options as the running agent.
- Only tested on PowerBeam 5AC / WA.v8.7.11 so far. A reboot of the device with the agent installed has not been tested yet.
