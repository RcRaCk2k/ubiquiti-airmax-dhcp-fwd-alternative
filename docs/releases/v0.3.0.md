**dhcp-snooping-82 0.3.0** adds an optional source guard bound to the DHCP leases, a frame type filter for transparent bridges, and support for airOS 6, where a word in the bridge comment takes the place of the missing DHCP relay switch. It remains a drop-in replacement for the airOS `/bin/dhcp-fwd`.

Tested on three production stations: two PowerBeam 5AC with WA.v8.7.15-cs (one IPv4 only, one with DHCPv6 prefix delegation and SLAAC) and one airOS 6 station with XW.v6.3.26-cs (AR934x, kernel 2.6.32). On the airOS 6 station the boot hook started the agent after a reboot before the wireless link was up, and the customer got its address with option 82 as soon as the link was there.

## New

- **Source guard** (`[source_guard] enable = yes`, off by default): a customer port may only use the addresses the DHCP server handed out, bound to the client MAC.
  - IPv4 with source MAC + IP, ARP with sender MAC + IP, IPv6 addresses (IA_NA) and delegated prefixes (IA_PD) with source MAC + address/prefix. Always allowed: DHCP itself, ARP probes from `0.0.0.0`, IPv6 link-local and `::` for duplicate address detection. VLAN tagged IP from a customer port is dropped so it cannot bypass the rules.
  - Renews only move the expiry in the agent; the ebtables rules change only when a binding appears, expires, is released or NAKed.
  - `max_bindings` counts IPv4 addresses, IPv6 addresses and prefixes separately: `1` allows one router with one of each. A new lease beyond the limit replaces the binding renewed longest ago, so a replaced router is not locked out.
  - **SLAAC:** many routers form their WAN address from the operator's router advertisement and use DHCPv6 only for the prefix. The agent learns the SLAAC prefixes from RAs on the uplink and allows each bound client's modified EUI-64 address in them (`slaac = eui64`, default), the whole /64 (`slaac = prefix`) or nothing (`slaac = no`).
  - `grace = SECONDS`: learn only, do not block, for this long after the start. `block_ip_only = no` also drops PPPoE and every other non-IP frame.
  - Bindings are kept in a lease file in RAM, so a restarted agent restores them. If ebtables rejects a rule the guard is removed again (fail open), unlike the DHCP rules.
- **Frame types** (`[interface] frame_types = any | untagged-only | vlan-only`): drop VLAN tagged, or untagged, frames that the bridge forwards between the agent's ports, e.g. a foreign VLAN leaking over a link meant to be a plain untagged bridge during a network migration. Only bridged traffic is filtered (chain `DHCP_SNOOPING_82_FT`, jumped to from `FORWARD`); the station's own traffic is not touched.
- **airOS 6 and the bridge comment:** the airOS 6 web UI has no DHCP relay switch, so the bridge's comment field controls the agent. Words of the form `key=value` count anywhere in the comment, e.g. `Customer X; dhcp-option-82=yes frame-types=untagged-only`:
  - `dhcp-option-82=yes|no` enables the agent for the bridge, or excludes it even with the airOS relay on (airOS 8 too),
  - `frame-types=...` overrides the default per bridge.

  Without the relay airOS starts no `dhcp-fwd`; the boot hook (`ensure`) adds the init line airOS would write. A small "Apply" on airOS 6 restarts nothing, so the agent reloads by itself when `/tmp/system.cfg` changes; without an enabled bridge it removes its rules and waits.
- **Configuration file shipped as an example:** `dhcp-snooping-82.conf.example` lists every key with its default. `install` copies it next to your `dhcp-snooping-82.conf` and creates that file only if it does not exist, so local settings survive updates. A file with just the keys that differ is enough.
- `--status` shows the source guard rules and bindings, `--check` the frame types per bridge.

## Upgrade from 0.2.0

```sh
# on the PC
sha256sum -c SHA256SUMS
tar xzf dhcp-snooping-82-0.3.0-mips.tar.gz
cd dhcp-snooping-82-0.3.0
scp -O dhcp-fwd dhcp-snooping-82.sh dhcp-snooping-82.conf.example root@DEVICE:/tmp/

# on the device
sh /tmp/dhcp-snooping-82.sh install                            # keeps your configuration
/etc/persistent/dhcp-snooping-82/dhcp-snooping-82.sh activate  # mounts the new binary, restarts the agent
sh /etc/persistent/dhcp-snooping-82/dhcp-snooping-82.sh install --save
```

The agent is off for about a second while it restarts. Without `enable = yes` in `[source_guard]` and without `frame_types` nothing changes in behaviour compared with 0.2.0.

## Things to know

- **airOS 6 has no `ebt_arp`:** the source guard then binds IPv4 and IPv6 as usual but cannot check ARP; it says so in the log and in `--status`.
- **"Apply" saves `/etc/persistent` to flash** on airOS, so an `install` without `--save` is kept after the next Apply as well.
- **Source guard after a reboot:** the lease file is in RAM and gone. The customer's router normally asks again after the link flap; if a switch keeps its link up, set a grace period longer than the DHCP renew interval (DHCPv6 renews can be hours apart).
- With `slaac = eui64` only the address formed from the client's MAC is allowed; routers using privacy addresses on the WAN side need `slaac = prefix`.
- Still true: standard (non-CS) firmware runs no boot hook, so call `ensure` after a reboot or comment change there.
